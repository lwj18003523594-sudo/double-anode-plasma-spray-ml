## 一、V1.6 产品目标（一段话）

V1.6 在不删减任何现有功能的前提下，完成四件事：① 对平台整体结构做细致化梳理——首页重排为「智能操作优先」的信息架构，各 Tab 内部按 Nature 论文的「方法—证据—结论」层级重组；② 将网页图表（Plotly）与论文导出图（matplotlib）全面重绘为 Nature 级专业风格（白底、中性灰+单信号色+单强调色、直接标注、统计诚信标注 n/误差棒/R²）；③ 在首页最显眼位置提供「智能一键导入」与「智能分析」两个核心按键，构成贯穿「导入 → 分析 → 结论」的智能工作流入口；④ 建立「全程可溯源」机制——每条智能分析结论都由真实计算结果生成并在界面标注数据支撑（R²、CV 指标、样本统计量、run_id、数据版本），杜绝任何模板化套话，使平台同时满足个人科研产出、组会/答辩演示、课题组共享工具三种场景。

## 二、增量需求池

### P0（必须实现——缺一则 V1.6 不成立）

#### P0-1 首页智能操作区（Smart Actions Hub）

- **需求描述**：首页顶部（研究主线卡片之上或紧邻其下）新增横向「智能操作区」，将「智能一键导入」与「智能分析」两个 primary 按键以最大视觉权重呈现，取代当前埋在页面中部的快速科研分析上传框。两个按键即 V1.5 快速科研分析（quick_analysis.py）的入口重构，不是新引擎。
- **验收标准**：
  1. 打开首页第一屏（1280×800 视口、不滚动）即可看到两个主按键，尺寸 ≥ 常规按钮 1.5 倍，使用强调色实底（区别于全站淡雅描边按钮）；
  2. 「智能一键导入」点击后弹出/展开拖放区，支持 XLSX/XLS/CSV，多 Sheet 自动分类（数据表/元数据表）并逐表独立运行——行为与 V1.5 quick_analyze_file 完全一致，不合并文献 Sheet；
  3. 「智能分析」在无待分析文件时引导导入；已有运行记录时一键生成最新 run 的智能分析摘要（见 P0-3）；
  4. Quick Run 仍写入 runs/quick_analysis/<run_id>/，不覆盖正式 models/；「设为正式模型」仍须用户主动确认——隔离铁律不变；
  5. 运行历史、promote 功能从首页折叠区完整保留。
- **涉及模块**：app.py（tab0 重构）、src/quick_analysis.py（入口适配，不改隔离逻辑）

#### P0-2 全程可溯源机制（Traceable Evidence）

- **需求描述**：建立「结论 → 证据」的强制绑定规范：智能分析、数据洞察、图表解读中每一条结论句必须携带可点开的证据标注。证据分三类，沿用 V1.5 insights.py 三源分级：**[直接数据]**（n、mean、std、CV%、min–max，来自事实行）、**[模型推断]**（R²/RMSE/MAE、CV 方式与折数、OOF、SHAP/FI）、**[数据来源]**（run_id、数据版本 hash、模型版本、Demo 标记）。
- **验收标准**：
  1. 智能分析摘要中每条结论句尾部有证据徽标（如 `[n=45 ｜ R²=0.87 ｜ Run_xxx]`），点击可展开该结论引用的全部数值、计算方式与来源文件路径；
  2. **反模板红线**：分析文本生成器必须从 metrics/统计量字典取值拼接；任一度量缺失时该句降级为「当前数据不足以支持该判断」而非套话——QA 需抽查 10 条结论，每条都能在 evidence JSON 中找到对应数值字段；
  3. Demo 数据结论必须醒目标注「模拟数据，不可用于正式科研结论」；
  4. 每个分析 run 目录内输出 evidence_manifest.json：结论 ID → {数值、计算函数名、数据版本、模型版本、代码行/模块名}；
  5. V1.5 figure_analysis.py 的禁用词纪律（无检验不得用"显著"、禁"最佳工艺"等绝对化词）全量继承并纳入 QA 检查清单。
- **涉及模块**：src/figure_analysis.py、src/insights.py、src/quick_analysis.py、app.py（证据徽标组件）、src/paper_output.py（manifest 透传）

#### P0-3 首页智能分析摘要卡（Smart Summary Card）

- **需求描述**：「智能分析」按键的输出载体：一张结构化摘要卡，在首页直接展示最新（或指定）run 的核心结果，而非仅给出目录路径。
- **验收标准**：
  1. 摘要卡包含：各 Stage 关键目标 R²/RMSE 表（真实计算值）、Top 特征重要性、数据覆盖一句话（沿用 coverage_text 的客观措辞）、Pareto 解数量（如有）、逐条结论带 P0-2 证据徽标；
  2. 每个数值都能点开溯源（联动 evidence_manifest）；
  3. 提供「跳转对应 Tab 深入查看」链接（③训练/⑤解析/⑥洞察/⑦逆向/⑧输出）；
  4. 分析失败/数据不足时如实展示失败原因与已通过/未通过的检查项（沿用 data_readiness_issues 输出），禁止显示半成品结论。
- **涉及模块**：app.py、src/quick_analysis.py、src/insights.py

#### P0-4 网页图表 Nature 级重绘（Plotly）

- **需求描述**：全平台 8 个 Tab 的 Plotly 图表统一按 Nature 纪律重绘样式：白底、一个中性灰家族 + 一个信号色家族（蓝=主方法）+ 一个强调色家族（樱花粉仅保留给强调），低饱和；系列家族一致性优先；直接标注优于图例；每张图必带统计诚信标注。
- **验收标准**：
  1. 建立统一 Plotly 模板模块（如 src/plot_style.py），所有图从该模块取色板与布局——散点/分布/重要性条形图色系一致；
  2. 模型评价类图（parity/residual）必须显示 n、R²、RMSE、CV 方式；散点类图显示误差棒定义说明（如有重复测量）；无标注视为不合格；
  3. 红/绿仅用于方向性语义（涨/跌），不用于装饰；
  4. hero panel 原则：每个 Tab 内一图一主结论，主面板放大，次级证据收缩到 expander；
  5. 字体维持 Times New Roman + 宋体衬线体系，图内字号层级与全局 spec 一致；
  6. 禁止使用 plotly 默认鲜艳循环色（如 #636EFA 系）直接出图。
- **涉及模块**：新建 src/plot_style.py，app.py 各 Tab 绘图代码调用改造

#### P0-5 论文导出图升级（matplotlib → Nature 风）

## 三、重点设计 A：首页智能操作区规格

### 布局

```
┌──────────────────────────────────────────────────────────────┐
│ ① 平台首页                                      [V1.6 状态徽标区] │
├──────────────────────────────────────────────────────────────┤
│  ◆ 智能操作区（Smart Actions）——首屏第一视觉                    │
│  ┌─────────────────────┐  ┌─────────────────────┐            │
│  │ ⬆ 智能一键导入        │  │ ✦ 智能分析          │            │
│  │   拖入 Excel/CSV      │  │   一键生成结论摘要   │            │
│  │   自动识别·逐表运行    │  │   每条结论可溯源     │            │
│  └─────────────────────┘  └─────────────────────┘            │
│  ① 导入 ─── ② 分析 ─── ③ 结论   （三步进度指示）                │
├──────────────────────────────────────────────────────────────┤
│  摘要卡（分析完成后展开，见 P0-3）                                │
├──────────────────────────────────────────────────────────────┤
│ ② 研究主线卡片 flow-card（保留 V1.5）                            │
│ ③ 运行历史 / 设为正式模型（折叠 expander，保留 V1.5）             │
│ ④ 平台状态面板（升级版，见 P1-2）                                │
└──────────────────────────────────────────────────────────────┘
```

### 交互流程

1. **智能一键导入**：点击 → 展开拖放区（首页内联，不跳页）→ 文件解析后即时反馈「识别到 N 个数据表（已跳过 M 个说明表），每个独立运行」→ 数据安全检查结果前置展示（critical 直接拦截并说明原因）→ 确认后运行，进度回调实时写入三步指示器 → 完成后摘要卡自动展开。
2. **智能分析**：三种态——
   - *空态*（无文件无 run）：按钮半透明，点击引导至导入；
   - *就绪态*（有文件未分析）：直接触发一键分析；
   - *结果态*（有最新 run）：生成/刷新摘要卡，并提供「下载结果包 ZIP」「查看运行目录」次级按钮。
3. **显眼程度量化**：两按钮为全站唯一实底强调色按钮（其余按钮维持白底描边），高度 ≥56px，占据首页宽度 2/3 以上；页面标题之外的第一视觉焦点。
4. **字段歧义处理**：高置信度别名自动映射（继承 V1.5 GENERIC_ALIAS），仅歧义字段弹出确认——「自动识别但绝不盲目猜测」原则不变。

### 结果展示（摘要卡）

- **顶部**：Run ID、研究模式、数据版本、样本量、日期，一行状态徽标。
- **证据区**：Stage 1/2/3（及 1.5 如启用）各目标 R²/RMSE/n 小表格（真实计算值）；Top 5 特征重要性横向条形图（复用统一 Plotly 模板）。
- **结论区**：3–6 条结论句，每句带证据徽标，可逐条点开溯源（evidence_manifest 联动）。
- **行动区**：跳转 ③⑤⑥⑦⑧ 深入操作的链接 + 下载 ZIP。

## 四、重点设计 B：全程可溯源机制

### 证据链三层结构

```
结论句（界面展示）
   └─ 证据徽标：[直接数据 n=45 · CV%=8.2]（hover 预览）
        └─ 证据详情（点击展开）：数值表 + 计算方式 + 来源
             └─ evidence_manifest.json（run 目录内）：结论ID → {
                  values: {...},          # 引用的全部数值
                  computed_by: "insights.coverage_stats",  # 计算入口
                  data_version: "auto_xxxx",
                  model_version: "...",
                  rows_filter: "data_origin ∈ {experimental, literature, cfd}",
                  files: ["Data_A01_...csv", "meta_....json"]
                }
```

### 生成纪律（写入实现规范，QA 逐条核对）

1. **取值即拼接**：所有结论文本由代码从 metrics/统计字典格式化生成，禁止手写字符串常量含数值；
2. **缺证降级**：任一引用度量缺失 → 该句替换为如实说明，不输出弱化版套话；
3. **标注最低集**：每条结论至少标注 n 与一个核心度量（R² 或统计量）+ run_id；
4. **三源不混**：[直接数据] 结论不得引用模型输出；[模型推断] 结论必须带 CV 方式限定；
5. **演示隔离**：Demo run 的所有结论句前缀「[演示数据]」；
6. **留档**：evidence_manifest.json 随 ZIP 一起打包，网页端可整体下载。

### 与现有机制的关系

## 五、重点设计 C：观感重设计方向（简洁大方）

### 设计原则

1. **一个页面一个主角**：每页一个主面板（主图或主操作），其余全部让位折叠；
2. **低饱和三家族色制**：中性灰（文字/网格/参考线）+ 信号蓝（主方法/数据系列）+ 樱花粉（强调/逆向设计点缀）——红绿只留给方向性语义；
3. **留白优先于装饰**：去除一切非功能性色块与阴影，卡片只用 1px 边框 + 3px 顶部色带（flow-card 语言保留并推广为全站卡片语言）；
4. **衬线学术气质保留**：Times New Roman + 宋体体系是科研身份的一部分，字号层级沿用 V1.5 spec（主标题 30–32 / 二级 23–25 / 模块 18–20 / 正文 15–16 / 辅助 13–14），只调密度不换字族。

### 色板方向（具体色值由架构师定稿，此处为方向约束）

| 家族 | 用途 | 方向 |
|------|------|------|
| 中性灰 | 正文 #2F3440、辅助 #7A8290、边框 #E5E9EF、底 #FAFBFC | 维持 V1.5 基调，微调对比度 |
| 信号蓝 | 数据系列、主按键、status-pill | 当前 #A9C9E5/#3D5A78 家族加深一档作为图表主色（≈#3C6E9F 量级），保持低饱和 |
| 强调粉 | 智能按键实底、强调标注、obj-card | 当前 #E8B8C0 加深至可读实底（≈#C4707F 量级），仅用于 ≤2 处/页 |
| 方向色 | 仅涨跌/优劣语义 | 低饱和绿 #6FA57C / 红 #C47070，禁作装饰 |

### 布局密度与信息层级

- **密度**：正文行高 1.6 不变；卡片间距统一 16/24 两档；每屏（1280×800）主要文字块 ≤3 个，超过即折叠；
- **层级**：页面导语（caption 级）→ 主面板（subheader + 主图/主操作）→ 次级证据（expander）→ 调试/高级项（深层折叠），四级封顶；
- **导航**：Tab 标签维持 8 个不变；Tab 内锚点由 status-pill + 导语承担，不新增页内菜单。
